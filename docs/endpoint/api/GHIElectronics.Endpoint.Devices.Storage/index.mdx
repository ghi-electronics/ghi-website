<h1 className="api-package-heading">GHIElectronics.Endpoint.Devices.Storage</h1>

Endpoint's SD cards and USB drives: insert and remove events, mounting (System.IO's DriveInfo).

## Classes

| Class | Summary |
|---|---|
| [DeviceConnectionEventArgs](./DeviceConnectionEventArgs.mdx) | Event data for `StorageController.ConnectionChanged`: one drive attached or detached. |
| [FileSystem](./FileSystem.mdx) | Mount / flush / unmount a drive the `Storage.StorageController` reported. Pass the `DeviceConnectionEventArgs.Hdc` from the event. |
| [StorageController](./StorageController.mdx) | The SD card slot or the USB drives. Events come on the library's storage thread. A drive that is pulled out is unmounted by the library. The SD card is at `/media/sd/`; USB drives get the first free `/media/usbN/`, as Windows gives the first free drive letter. A controller stays alive until it is disposed. |

## Delegates

| Delegate | Summary |
|---|---|
| [ConnectionChangedEventHandler](./ConnectionChangedEventHandler.mdx) | Handler for `StorageController.ConnectionChanged`. Called on the library's storage thread when a drive is attached or detached; the drives already plugged in at `StorageController.Enable` time are reported too. |
