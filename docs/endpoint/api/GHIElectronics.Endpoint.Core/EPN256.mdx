# EPN256 Class

**Package:** `GHIElectronics.Endpoint.Core`<br/>**Namespace:** `GHIElectronics.Endpoint.Core`

The EPN256 module: its pin names and the pin setup the other libraries use. Pin numbers are packed as `port * 16 + line`. Mirrors `Core.EPM815` so sample code reads the same shape across boards.

```csharp
public static class EPN256
```

## Nested Types

| Type | Kind | Summary |
|---|---|---|
| [EPN256.Adc](./EPN256_Adc.mdx) | Class | The ADC channels bundled with EPN256. Call `Adc.ReadMillivolts` on `Adc.Eadc0` and the channel index to read a channel. Channels 0 - 3 of `Adc.Eadc0` drive the resistive touch screen on the reference panel; stay off those unless the touch subnode has been removed. |
| [EPN256.Can](./EPN256_Can.mdx) | Class | CAN interfaces bundled with EPN256. `Can.Initialize` claims a port's pins and starts it; `Can.UnInitialize` releases them. Interface names are stable, so `Can.Can0` is always `can0`. |
| [EPN256.Gpio](./EPN256_Gpio.mdx) | Class | GPIO pins and the module-level pin numbering scheme. Pin numbers are packed as `port * 16 + line`, where port is a `Gpio.Port` value (A..N) and line is 0..15. Most applications should use the standard `Gpio.GpioController` through `Gpio.Driver` rather than the module-level helpers. |
| [EPN256.I2c](./EPN256_I2c.mdx) | Class | The I2C buses bundled with EPN256. Use with .NET's `System.Device.I2c`. `I2c.Initialize` brings up the bus and muxes its pins; `I2c.UnInitialize` tears it down so the pins return to free GPIO. The buses are kept unprobed until a userspace library needs them (pay-for-use rule). Each constant is the bus number for `I2cConnectionSettings` (`/dev/i2c-N`). |
| [EPN256.Pwm](./EPN256_Pwm.mdx) | Class | PWM channels bundled with EPN256, for `System.Device.Pwm`. The PWM controller stays unprobed and its pins stay free GPIO until `Pwm.Initialize` loads its driver. Reverse with `Pwm.UnInitialize`. The `EPWM_` number is the instance number; the sysfs `pwmchipN` is probe-order and is resolved at `Pwm.Initialize` time, so application code never has to deal with it. |
| [EPN256.SerialPort](./EPN256_SerialPort.mdx) | Class | The user-facing serial ports (UARTs) bundled with EPN256, for `System.IO.Ports.SerialPort`. The console UART is reserved for the kernel and not exposed here. The three ports below have stable names, so `SerialPort.Uart11` is always `/dev/ttyS11`. `SerialPort.Initialize` brings up the UART, claiming its TX / RX pins; `SerialPort.UnInitialize` returns them to free GPIO. Both are safe to call multiple times; the first `SerialPort.Initialize` does the work and the matching `SerialPort.UnInitialize` undoes it. |
| [EPN256.Spi](./EPN256_Spi.mdx) | Class | SPI controllers bundled with EPN256. At boot nothing probes, so pins stay free GPIO; `Spi.Initialize` brings up the bus and `/dev/spidev<N>.0` appears for userspace. Pin assignments are chosen so none collide with the EPN256 bundled hardware, the console UART, or the resistive touch pins. |
| [EPN256.StorageController](./EPN256_StorageController.mdx) | Class | SD cards and USB drives on EPN256. Use with the `GHIElectronics.Endpoint.Devices.Storage` package. |
