# Getting Started with Endpoint

Endpoint runs **full .NET, Python, and C/C++** on a circuit. All three share one set of APIs, so what you learn in one language travels with you. You debug them over a USB cable, no SSH, with no keys, passwords, or IP addresses.

:::note[Evaluation hardware]
[Endpoint Domino24](hardware.mdx) is the evaluation board we built for Endpoint. We have not released SoMs or dev boards yet, because we are still shaping what the commercial product should be. Tell us what you need on the [forum](https://forums.ghielectronics.com/c/endpoint/34): what form factor, which peripherals, and whether wireless is a requirement.
:::

## Languages and tools

| Language | Version | VS Code | Visual Studio |
|---|---|---|---|
| **C#** | .NET 11 | Yes | Yes |
| **Python** | Python 3.14 | Yes | No |
| **C and C++** | C23 and C++23, with no toolchain to install | Yes | No |

## What you'll need

- **[Endpoint Domino24](hardware.mdx)**
- A **USB-C cable**
- A **microSD card** of at least 4 GB
- **VS Code** for any language, or **Visual Studio** for .NET

## Step 1: Prepare the board

1. Download the latest Endpoint OS image from the [Downloads](downloads.mdx) page.
2. Write the image to the microSD card with a disk imaging tool such as balenaEtcher.
3. Insert the card into Domino24 and connect it to your PC with the USB-C cable.
4. Wait for the **USER LED** to light, which shows the board has finished booting.

## Step 2: Install the extension

<Tabs groupId="ide">
<TabItem value="vs" label="Visual Studio" default>

Visual Studio supports **.NET (C#)**.

1. **Visual Studio 2026** (Community, Professional or Enterprise). VS 2022 17.9+ also works.
2. The matching **.NET SDK** installed and on PATH ([download](https://dotnet.microsoft.com/download)).
3. The **Endpoint Debugger** extension from the [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=ghielectronics.Endpoint-VS-Debugger). In Visual Studio, open **Extensions > Manage Extensions** and search for *"Endpoint"*.

</TabItem>
<TabItem value="vscode" label="Visual Studio Code">

Visual Studio Code supports **.NET (C#)**, **Python**, and **C/C++**, all three languages from the same extension.

1. **Visual Studio Code**.
2. The **Endpoint Debugger** extension from the [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=ghielectronics.endpointvscdebugger). In VS Code, open the **Extensions** view and search for *"Endpoint"*.
3. For each language you want to use:
   - **.NET (C#)**: the matching [.NET SDK](https://dotnet.microsoft.com/download) and the [C#](https://marketplace.visualstudio.com/items?itemName=ms-dotnettools.csharp) extension.
   - **Python**: [Python](https://www.python.org/downloads/) and the [Python](https://marketplace.visualstudio.com/items?itemName=ms-python.python) + [Python Debugger](https://marketplace.visualstudio.com/items?itemName=ms-python.debugpy) extensions.
   - **C/C++**: the [C/C++](https://marketplace.visualstudio.com/items?itemName=ms-vscode.cpptools) extension.

</TabItem>

## Step 3: Create a project

Every Endpoint template is a ready-to-run blink application: it blinks the USER LED and prints a counter. Core and GPIO are referenced out of the box, so the project builds and runs without any extra setup.

<Tabs groupId="ide">
<TabItem value="vs" label="Visual Studio" default>

1. **File > New > Project...** → search *"Endpoint"* → choose **Endpoint App (C#)**. Give it a name and location.

   ![Endpoint App (C#) template in the Visual Studio new-project dialog](/img/docs/endpoint/vs-new-project-template.png)

</TabItem>
<TabItem value="vscode" label="Visual Studio Code">

1. Plug the board in with USB. The status bar at the bottom of VS Code shows **Endpoint** when the board is detected:

   ![Endpoint shown in the VS Code status bar](/img/docs/endpoint/vscode-endpoint-statusbar.png)

2. **Ctrl+Shift+P** → **Endpoint: New Project...** → pick a language (**.NET**, **Python** or **C/C++**), a name and a folder. VS Code opens the new project.

   ![New Endpoint Project language picker in VS Code](/img/docs/endpoint/vscode-new-project-language.png)

</TabItem>
</Tabs>

## Step 4: Deploy and run

Make sure the **USER LED** on the board is on. A lit USER LED means the board has finished booting and is ready to accept a new program. If the LED is still off, wait a few seconds; a cold boot takes about three.

Press **F5** or **Ctrl+F5**. Either command stops any application currently running on the board — including one set to run at boot — before deploying the new build, so you never need to disable the previous program by hand.

<Tabs groupId="ide">
<TabItem value="vs" label="Visual Studio" default>

Press **F5**. Visual Studio builds the project, deploys it to the board over USB, and starts it under the debugger. Breakpoints, step, locals, and watch work as usual.

The **USER LED** blinks every 500 ms, and the Output window prints one counter line per blink:

```
Hello Endpoint. Counter: 1
Hello Endpoint. Counter: 2
Hello Endpoint. Counter: 3
...
```

**Project settings** live under the project's **Endpoint** property page:

![Endpoint project settings in Visual Studio](/img/docs/endpoint/vs-endpoint-settings.png)

- **Transport**: how Visual Studio talks to the board. USB today.
- **Device**: **Endpoint** runs the program on the board; **Desktop** runs it locally on the PC for quick checks.
- **Firmware**: check for updates, erase the application that is set to run at boot.

**Run at boot:** press **Ctrl+F5** instead of F5. The project is compiled with Native AOT and set to start automatically on power-on. A C# blink application goes from power-on to running in under three seconds.

</TabItem>
<TabItem value="vscode" label="Visual Studio Code">

Press **F5**. The extension builds the project, deploys it to the board over USB, and starts it under the debugger.

The **USER LED** blinks every 500 ms, and the Debug Console prints one counter line per blink:

```
Hello Endpoint. Counter: 1
Hello Endpoint. Counter: 2
Hello Endpoint. Counter: 3
...
```

If the board is not connected, is in use by another program, or is not responding, F5 stops with a clear message instead of running silently.

**Run at boot:** press **Ctrl+F5** instead of F5. The project is compiled with Native AOT and set to start automatically on power-on. A C# blink application goes from power-on to running in under three seconds.

## Step 5: Add a package

A new project already references **Core** and **GPIO**. Add the other Endpoint drivers (ADC, DAC, PWM, Display, Touch, Camera, Network, UI, and more) or any third-party library when you need them, and update to a newer version the same way.

<Tabs groupId="lang">
<TabItem value="dotnet" label=".NET (C#)" default>

From the project folder, add or update a package with `dotnet add package`:

```
dotnet add package GHIElectronics.Endpoint.Devices.Adc --prerelease
```

In Visual Studio, use **Manage NuGet Packages...** on the project and check **Include prerelease** during the 0.5.x preview. Every third-party NuGet package installs the same way.

</TabItem>
<TabItem value="python" label="Python">

Open a terminal in VS Code (**Terminal > New Terminal**) and run `pip install`:

```
pip install GHIElectronics.Endpoint.Devices.Adc
pip install pyserial
```

Packages install into the project's `packages/` folder and are copied with your program on F5. Third-party packages such as `pyserial`, `numpy`, and `pillow` install the same way.

</TabItem>
<TabItem value="cpp" label="C/C++">

The full C/C++ API is bundled with the extension — no package step. Include the header and use the namespace that matches each driver:

```cpp
#include <endpoint.h>

using namespace GHIElectronics::Endpoint::Core;
using namespace GHIElectronics::Endpoint::Devices::Adc;

AdcController adc;
auto pin = adc.OpenPin(EPDomino24::Adc::PA0);
double volts = pin.ReadVoltage().Volts();
```

Third-party C/C++ source can be dropped into the project folder; every `.cpp` next to `main.cpp` is built into the program.

</TabItem>
</Tabs>
