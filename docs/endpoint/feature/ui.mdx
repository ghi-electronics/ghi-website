The `GHIElectronics.Endpoint.UI` package is a widget library — Button, Label,
Container, Image, TextBox, Slider, CheckBox and more — built on an embedded
graphics engine. Each widget is created from a parent (any other widget, or a
`Screen`), given position and size, and raises events like `Clicked` or
`ValueChanged` when the user interacts with it. All widget updates must
happen on the UI thread; the library runs single-threaded so a background
thread cannot touch widgets directly (see [UiTimer](#periodic-updates) below).

## Getting started

The full lifecycle is: enable the display, initialize the UI, wire a
touchscreen (if any), build widgets on the active screen, run the event
loop.

```csharp
using GHIElectronics.Endpoint.Devices.Display;
using GHIElectronics.Endpoint.UI;

// 1. Display
using var display = DisplayController.GetDefault();
if (display == null) return;
display.Enable();

// 2. UI
UI.Initialize();

// 3. Touch (optional — needed only for touch input)
TouchBridge.Attach();
// touch.OnChangedEvent += (s, e) => TouchBridge.Feed(e.Points[0].X, e.Points[0].Y, pressed: ...);

// 4. Build widgets on the active screen
var screen = Screen.Active;
screen.BackgroundColor = 0x101828;

var hello = new Label(screen) {
    Text = "Hello Endpoint",
    Color = 0xFFFFFF,
    FontSize = 24,
    X = 20, Y = 20,
};

var button = new Button(screen) {
    Text = "Click me",
    X = 20, Y = 80,
    Width = 160, Height = 48,
};
button.Clicked += (s, e) => hello.Text = "Clicked!";

// 5. Run the event loop (blocks the thread)
UI.Run();
```

Call `UI.Stop()` from any thread to exit the loop and let `UI.Run()` return.

## Widgets

Every widget inherits common positioning and styling from `Widget`:

- `X`, `Y`, `Width`, `Height` — pixels, relative to the parent's top-left.
- `Visible` — show/hide (keeps the widget allocated).
- `BackgroundColor` — `0x00RRGGBB`.
- `SetBackgroundGradient(start, end, direction)` — linear gradient.
- `SetMargin(left, top, right, bottom)` — WPF-style margin, works in any parent.
- `SetBackgroundImage(bytes, w, h)` — tiled RGB565 image.
- `Dispose()` — destroy the widget.

### Label

Static text display.

```csharp
var label = new Label(parent) {
    Text = "Temperature: 23 °C",
    Color = 0x00FF00,
    FontSize = 18,
    TextAlignment = TextAlignment.Center,
    X = 10, Y = 10, Width = 200, Height = 30,
};
```

### Button

Push button that fires `Clicked` on tap.

```csharp
var button = new Button(parent) {
    Text = "Save",
    BackgroundColor = 0x2E7D32,
    TextColor = 0xFFFFFF,
    FontSize = 20,
    X = 50, Y = 100, Width = 120, Height = 40,
};
button.Clicked += (s, e) => Console.WriteLine("Saved");
```

### CheckBox / RadioButton / Switch

Two-state toggles. Each raises `ValueChanged` on toggle and exposes
`IsChecked`.

```csharp
var cb = new CheckBox(parent) {
    Text = "Enable Wi-Fi",
    X = 10, Y = 10,
};
cb.ValueChanged += (s, e) => Console.WriteLine($"Checked = {cb.IsChecked}");
```

### Slider

Draggable value selector. Default range 0–100.

```csharp
var slider = new Slider(parent) {
    Minimum = 0, Maximum = 255,
    X = 10, Y = 200, Width = 300, Height = 20,
};
slider.Value = 128;
slider.ValueChanged += (s, e) => Console.WriteLine(slider.Value);
```

### TextBox

Single-line editable text with placeholder. Pair with a [Keyboard](#on-screen-keyboard)
for on-screen typing. The `Text` getter reads live from the UI.

```csharp
var tb = new TextBox(parent) {
    Placeholder = "Enter name...",
    X = 10, Y = 10, Width = 200, Height = 32,
};
tb.ValueChanged += (s, e) => Console.WriteLine(tb.Text);
```

### Image

Displays an RGB565 bitmap.

```csharp
var img = new Image(parent) { X = 20, Y = 20, Width = 64, Height = 64 };
img.SetSource(rgb565Bytes, srcWidth: 64, srcHeight: 64);
```

### Layout containers

- **Container** — a plain rectangular area that holds children (positions
  are absolute to its top-left).
- **StackPanel** — stacks children vertically (default) or horizontally;
  set `Orientation` and `Spacing`.
- **DockPanel** — WPF-style docking (`Dock.Top` / `Bottom` / `Left` / `Right` / `Center`).
- **Grid** — rows and columns.
- **Border** — paints a border around a child area with `Thickness`,
  `BorderBrush` (color), `CornerRadius`, and inner `Padding`.

```csharp
var stack = new StackPanel(parent) {
    X = 10, Y = 10, Width = 200, Height = 300,
};
stack.Orientation = Orientation.Vertical;
stack.Spacing = 8;

new Label(stack) { Text = "One" };
new Label(stack) { Text = "Two" };
new Label(stack) { Text = "Three" };
```

### Chart and Gauge

```csharp
var chart = new Chart(parent) {
    X = 10, Y = 10, Width = 400, Height = 200,
    Mode = ChartMode.Line,
    DivisionAxisY = 4,
};
chart.SetColors(pointColor: 0x1E88E5, areaColor: 0x90CAF9, labelColor: 0xFFFFFF);
chart.SetPoints(new[] { 10, 25, 18, 30, 42, 36, 55 });
```

```csharp
var gauge = new Gauge(parent, 200, 200) {
    X = 20, Y = 40,
    SweepAngle = 270,
    EnableScale = true,
};
gauge.SetRange(0, 100);
gauge.Value = 65;
```

### MessageBox

A modal popup with Yes/No/OK buttons.

```csharp
var mb = new MessageBox(parent);
mb.Show("Reboot the board?", "Confirm", MessageBox.Buttons.YesNo);
mb.ButtonClicked += (s, e) => Console.WriteLine($"Picked: {e.Result}");
```

### On-screen keyboard

A software keyboard the user can type into with their finger. Normally
paired with a `TextBox`.

```csharp
var tb = new TextBox(parent) { X = 10, Y = 10, Width = 300, Height = 36 };
var kb = new Keyboard(parent) { X = 10, Y = 60, Width = 460, Height = 180 };
kb.AttachTo(tb);
```

## Multiple screens

A `Screen` is a top-level container with no parent. More than one screen
can exist at a time; only one is displayed at a time. Switching screens is
one call to `Load()`.

```csharp
var home   = new Screen();
var setup  = new Screen();

new Button(home) {
    Text = "Settings…",
    X = 10, Y = 10, Width = 120, Height = 40,
}.Clicked += (s, e) => setup.Load();

new Button(setup) {
    Text = "Back",
    X = 10, Y = 10, Width = 100, Height = 40,
}.Clicked += (s, e) => home.Load();

home.Load();
UI.Run();
```

`Screen.Active` returns the currently-displayed screen (useful when you
want to attach widgets to whatever is on-screen at startup).

## Periodic updates

The UI library is single-threaded — widget properties can only be touched
from the UI thread. Use `UiTimer` to schedule periodic updates that run on
the correct thread:

```csharp
var gauge = new Gauge(screen, 200, 200) { X = 20, Y = 20 };
gauge.SetRange(0, 100);

var phase = 0.0;
var timer = new UiTimer(100, () => {
    gauge.Value = (int)(50 + 50 * Math.Sin(phase));
    phase += 0.1;
});
```

The timer fires every `periodMs` milliseconds on the UI thread; dispose
the `UiTimer` to cancel it.

## Touch input

Touches get into the UI through the [Touch](touch-screen.mdx) package via
`TouchBridge.Feed(x, y, pressed)`. Once wired, the widget under the finger
raises `Clicked`, `ValueChanged`, drag events, etc. automatically — the
application code does not need to compute hit-testing.

See the [Touch Screen](touch-screen.mdx) page for the chip driver pattern.

## Designer

The on-device widget tree can also be laid out visually in the GHI UI
designer (browser-based), which exports a C#, Python or C/C++ file you
drop into your project. Code written by hand and code generated by the
designer target the exact same API.
