<h1 className="api-package-heading">GHIElectronics.Endpoint.Core</h1>

Core of the Endpoint libraries: board pin names and pin setup.

## Classes

| Class | Summary |
|---|---|
| [CanController](./CanController.mdx) | Chip-neutral entry point for CAN-bus setup. Call once before using the CAN device package: it muxes the TX/RX pins and brings the `canN` network interface up at the chosen bitrate. |
| [EPDomino24](./EPDomino24.mdx) | EP-Domino24 Rev B: a board variant of the EPM815 module with a 40-pin header, two mikroBUS sockets and a handful of onboard components. Same chip and firmware as `Core.EPM815`; this class is a thin re-naming layer that lists only the peripherals and pins actually bonded on the board, so application code reads what a user looking at the EP-Domino24 silkscreen expects. |
| [EPM815](./EPM815.mdx) | The EPM815 module: its pin names and the pin setup the other libraries use. Pin numbers are port * 16 + pin, with port Z after port I. |
| [Events](./Events.mdx) | System event hooks used by the device libraries. Placeholder: the kernel log scanner that fed this class is parked; the class stays as the cross-library event sink for future use. |
| [I2cController](./I2cController.mdx) | Chip-neutral entry point for I2C setup. Call once before using `I2c.I2cDevice`: it brings up the bus and muxes its pins. Dispatches to the right chip helper based on the board detected at startup. |
| [NativeRpmsgHelper](./NativeRpmsgHelper.mdx) | Low-level helper used by other libraries to talk to the firmware's hardware timing helper. Data is exchanged as 32-bit words in fixed-size blocks of `NativeRpmsgHelper.BlockSize` words. Most applications never call this directly; `Core.EPM815`-based classes such as `DigitalSignalController` use it internally. |
| [NativeUtils](./NativeUtils.mdx) | Low-level helpers backed by the native `nativeutils.so` library: a CPU wait-for-interrupt and a hardware-assisted JPEG to RGB888 decoder. |
| [Processor](./Processor.mdx) | Identifies the processor the firmware is running on. Libraries that need board-specific behaviour read `Processor.Name` and compare against the processor-id constants exposed here. |
| [PwmController](./PwmController.mdx) | Chip-neutral entry point for PWM setup. Call once before using `Pwm.PwmChannel`: it brings up the PWM channel and muxes its pin. |
| [Script](./Script.mdx) | Runs an external program and collects what it prints. Used internally by the Endpoint libraries where a direct API is not yet available; prefer the direct API where one exists. |
| [SerialPortController](./SerialPortController.mdx) | Chip-neutral entry point for UART / serial-port setup. Call once before using `System.IO.Ports.SerialPort`: it muxes the TX/RX pins (plus RTS/CTS when flow control is on) and makes `/dev/ttyS*` usable. |
| [SpiController](./SpiController.mdx) | Chip-neutral entry point for SPI setup. Call once before using `Spi.SpiDevice`: it brings up the bus and muxes its pins. |
