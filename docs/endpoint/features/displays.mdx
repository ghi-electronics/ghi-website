Endpoint supports two display categories:

- **Parallel TFT**: a panel wired directly to the board's parallel RGB
  controller. Fastest option; refresh runs off the hardware without any CPU
  work.
- **Serial (SPI / I2C)** displays and **character displays**: any panel you
  can drive from a bus. The next sections cover both.

The parallel display is driven through
`GHIElectronics.Endpoint.Devices.Display`. Panel timings and backlight pin
live in `/config/display.json`, so they are set once and the application
simply opens, enables and flushes.

## Parallel display

### One-time configuration

Write the panel's timings and backlight pin to the config partition. You
only have to do this once per board (settings persist across reboots).

<Tabs groupId="lang">
<TabItem value="dotnet" label=".NET" default>

```csharp
using GHIElectronics.Endpoint.Core;
using GHIElectronics.Endpoint.Devices.Display;

var settings = new DisplaySettings {
    Type = DisplayType.Parallel,
    EnableAtBoot = false,                     // true = board brings the panel up during boot
    Logo = null,                              // 24-bit BMP filename on /config, or null
    Backlight = new BacklightSettings {
        Pin = EPDomino24.Backlight,           // or -1 to leave the backlight alone
        ActivePolarity = SignalPolarity.ActiveHigh,
    },
    Parallel = new ParallelLcdSettings {
        Width        = 480, Height = 272,
        PixelClockHz = 10_000_000,
        HFrontPorch  = 2, HBackPorch = 2, HSync = 41,
        VFrontPorch  = 2, VBackPorch = 2, VSync = 10,
        BitsPerPixel = 16,                    // 16 = RGB565, 24 = RGB888
    },
};
DisplayController.SetSettings(settings);
```

### Enable and show pixels

Once configured, open the controller, enable it, and push a frame. The
pixels can come from any .NET graphics library (see [Graphics](graphics/index.mdx))
or from your own code.

<Tabs groupId="lang">
<TabItem value="dotnet" label=".NET" default>

```csharp
using var display = DisplayController.GetDefault();   // null if Type is None
if (display == null) return;

display.Enable();

// Pixel buffer in RGB565 (width * height * 2 bytes)
var pixels = new byte[display.Width * display.Height * 2];
// ... fill the buffer ...

display.Flush(pixels);                                 // defaults to Rgb565
```

</TabItem>

### Boot logo

partition and call `ShowLogo()` right after `Enable()` to paint it:

## Serial (SPI / I2C) displays

SPI and I2C panels (and any other non-parallel panel such as UART or an
HDMI bridge) are driven by their own `DisplayController` subclass. The
abstract contract is small:

- `Enable`: run the panel's power-up / init sequence
- `Disable`: power it down
- `Flush`: push pixels
- `Width` / `Height` / `IsEnabled`: visible panel size and state

Application code uses the same `Enable` / `Flush` pattern as the built-in
parallel panel, so a graphics stack written against `DisplayController` works
against either. `GetDefault()` only returns the parallel panel; a serial
driver is constructed directly.

### Using a ready-made driver

GHI Electronics publishes a driver for the HiLetgo ILI9341 240x320 SPI
TFT in all three languages. Source on GitHub:

- **.NET** &mdash; [`GHIElectronics.Endpoint.Drivers.HiLetgo.ILI9341`](https://github.com/ghi-electronics/endpoint-drivers/tree/main/dotnet/GHIElectronics.Endpoint.Drivers/HiLetgo/GHIElectronics.Endpoint.Drivers.HiLetgo.ILI9341) (NuGet package)
- **Python** &mdash; [`ili9341.py`](https://github.com/ghi-electronics/endpoint-drivers/tree/main/python/GHIElectronics.Endpoint.Drivers/HiLetgo/GHIElectronics.Endpoint.Drivers.HiLetgo.ILI9341) (drop the file into the project)
- **C/C++** &mdash; [`Ili9341.h`](https://github.com/ghi-electronics/endpoint-drivers/tree/main/cpp/GHIElectronics.Endpoint.Drivers/HiLetgo/GHIElectronics.Endpoint.Drivers.HiLetgo.ILI9341) (header-only, drop the file into the project)

All three use the same `Initialize` + `Flush` pattern.

<Tabs groupId="lang">
<TabItem value="dotnet" label=".NET" default>

```csharp
using System.Device.Gpio;
using System.Device.Spi;
using GHIElectronics.Endpoint.Core;
using GHIElectronics.Endpoint.Drivers.HiLetgo.ILI9341;

using var gpio = new GpioController(new EPDomino24.Gpio.Driver());
using var spi  = SpiDevice.Create(ILI9341Controller.GetConnectionSettings(EPDomino24.Spi.Spi1));

using var tft = new ILI9341Controller(
    spi:   spi,
    cs:    EPDomino24.Gpio.Pin.PA14,
    dc:    EPDomino24.Gpio.Pin.PA10,
    reset: EPDomino24.Gpio.Pin.PF4,
    gpio:  gpio);
tft.SwapRedBlue = true;        // set for modules where yellow shows as cyan
tft.Enable();

// Pixel buffer in RGB565 (width * height * 2 bytes)
var pixels = new byte[tft.Width * tft.Height * 2];
// ... fill the buffer ...
tft.Flush(pixels);
```

:::note Wiring gotchas (worth knowing even with the driver)
- **Chip select** is driven by a GPIO, not by the SPI controller's hardware NSS.
  The driver opens the pin you pass and toggles it around each transaction.
  On .NET, `SpiConnectionSettings` needs `chipSelectLine: 0` explicitly —
  Microsoft's Linux SPI stack does not accept `-1`.
- **Data / Command** pin: ILI9341 distinguishes commands from pixel data
  by a separate GPIO (D/C). Low = command byte, high = data byte.
- **Reset** pin: an active-low pulse brings the chip out of reset
  reliably at startup. Tie to 3.3 V or leave unwired only if your module
  has an on-board reset circuit.
- **Pixel format** on the wire is 16 bpp **big-endian**, but Canvas
  writes RGB565 **little-endian** (ready for `/dev/fb0`). The driver
  byte-swaps each pixel in `Flush`; you never see the raw bytes.
- **Red / Blue swap**: some HiLetgo and eBay modules have the physical
  color filter wired as BGR regardless of what the chip's MADCTL bit
  says, so yellow renders as cyan and red as blue. Set
  `SwapRedBlue = true` for those modules.
- **Backlight** on most 2.2"–2.8" ILI9341 modules has a current-limit
  resistor on board; tie LED to +3.3 V for always-on, or drive from a
  PWM pin if you want to dim it.
:::


### Writing your own driver

To support a panel we do not ship a driver for, subclass `DisplayController`
and drive the hardware through the standard SPI / I2C / GPIO APIs. The
skeleton is small:

<Tabs groupId="lang">
<TabItem value="dotnet" label=".NET" default>

```csharp
using System;
using System.Device.Gpio;
using System.Device.Spi;
using GHIElectronics.Endpoint.Devices.Display;
using PixelFormat = System.Drawing.Imaging.PixelFormat;

public sealed class MyPanelController : DisplayController {
    private readonly SpiDevice spi;
    private readonly GpioController gpio;
    private readonly int dcPin, resetPin;
    private bool enabled;

    public MyPanelController(SpiDevice spi, int dc, int reset, GpioController gpio) {
        this.spi = spi;
        this.gpio = gpio;
        this.dcPin = dc;
        this.resetPin = reset;
        this.gpio.OpenPin(dc, PinMode.Output);
        this.gpio.OpenPin(reset, PinMode.Output);
    }

    public override int  Width     => 240;
    public override int  Height    => 320;
    public override bool IsEnabled => this.enabled;

    public override void Enable() {
        // reset pulse + vendor init sequence over SPI ...
        this.enabled = true;
    }

    public override void Disable() {
        // put the panel to sleep
        this.enabled = false;
    }

    public override void Flush(ReadOnlySpan<byte> pixels, PixelFormat format,
                               int x, int y, int width, int height) {
        // 1) set the panel's draw window to (x, y, width, height)
        // 2) send pixels over SPI in the panel's native format
    }

    public override void Dispose() {
        try { this.Disable(); } catch { }
        this.gpio.ClosePin(this.dcPin);
        this.gpio.ClosePin(this.resetPin);
        this.spi.Dispose();
    }
}
```

from GHIElectronics.Endpoint.Devices.Gpio import GpioController, PinMode
from GHIElectronics.Endpoint.Devices.Display import DisplayController, PixelFormat

class MyPanelController(DisplayController):
    def __init__(self, spi, dc, reset, gpio):
        self._spi = spi
        self._gpio = gpio
        self._dc_pin = dc
        self._reset_pin = reset
        self._enabled = False
        gpio.OpenPin(dc, PinMode.Output)
        gpio.OpenPin(reset, PinMode.Output)

    @property
    def Width(self): return 240

    @property
    def Height(self): return 320

    @property
    def IsEnabled(self): return self._enabled

    def Enable(self):
        # reset pulse + vendor init sequence over SPI ...
        self._enabled = True

    def Disable(self):
        # put the panel to sleep
        self._enabled = False

    def _Flush(self, pixels, format_, x, y, width, height):
        # 1) set the panel's draw window to (x, y, width, height)
        # 2) send pixels over SPI in the panel's native format
        pass

    def Dispose(self):
        try:
            self.Disable()
        except Exception:
            pass
        self._gpio.ClosePin(self._dc_pin)
        self._gpio.ClosePin(self._reset_pin)
        self._spi.Dispose()

#include <endpoint/Gpio.h>

        : spi_(std::move(spi)), gpio_(gpio), dcPin_(dc), resetPin_(reset) {
        gpio.OpenPin(dc, PinMode::Output);
        gpio.OpenPin(reset, PinMode::Output);
    }

    int  Width()     const override { return 240; }
    int  Height()    const override { return 320; }
    bool IsEnabled() const override { return enabled_; }

    void Enable() override {
        // reset pulse + vendor init sequence over SPI ...
        enabled_ = true;
    }

    void Disable() override {
        // put the panel to sleep
        enabled_ = false;
    }

    using DisplayController::Flush;
    void Flush(const uint8_t* /*pixels*/, size_t /*length*/, PixelFormat /*format*/,
               int /*x*/, int /*y*/, int /*width*/, int /*height*/) override {
        // 1) set the panel's draw window to (x, y, width, height)
        // 2) send pixels over SPI in the panel's native format
    }

    ~MyPanelController() override {
        try { Disable(); } catch (...) {}
        gpio_.ClosePin(dcPin_);
        gpio_.ClosePin(resetPin_);
        spi_.Dispose();
    }

private:
    SpiDevice      spi_;
    GpioController& gpio_;
    int            dcPin_;
    int            resetPin_;

};

## Character displays

![Character Display](/img/docs/endpoint/character-display.jpg)

Character-matrix LCDs (2x16, 4x20, etc.) use the standard
[Iot.Device.CharacterLcd](https://learn.microsoft.com/en-gb/dotnet/api/iot.device.characterlcd?view=iot-dotnet-latest)
library from .NET IoT. Wire the panel to any GPIO/I2C/SPI pins and drive it
with the same code you would use on any .NET IoT board.
