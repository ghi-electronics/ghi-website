# Light and Logic

The potentiometer was a well-behaved sensor: linear, predictable, and identical for everyone. A **photoresistor** is none of those things. It doesn't even produce a voltage — you have to build a circuit that turns its resistance into one.

This lesson is about the gap between a reading and a decision. You'll build a night-light that switches an LED on when the room gets dark — and then fix the flicker that every first attempt has.

About 40 minutes.

## What you'll learn

- How to build your own voltage divider so a resistance can be read by the ADC
- Why a sensor reading means nothing until you calibrate it to your own room
- How to turn a number into a decision with a threshold
- Why a single threshold flickers, and how **hysteresis** fixes it

## What you'll need

- From the kit:
  - Light sensor (photoresistor)
  - 1× 27 kΩ resistor (red · violet · orange)
  - 1× LED and 1× 220 Ω resistor
  - Jumper wires

## Pin reference

| Connection | FEZ Flea | FEZ Bit |
|---|---|---|

## Step 1 — Create the project

## Step 2 — Build a voltage divider

A photoresistor's resistance changes with light: a few kilohms in bright light, hundreds of kilohms in the dark. The ADC can't measure resistance — only voltage. So pair the photoresistor with a fixed resistor and read the point between them, exactly like the potentiometer's wiper in [Analog Input](analog-input.mdx#the-potentiometer-is-a-voltage-divider).

```
3.3V ──┬──────────────┐
       │              │
  [photoresistor]     │   bright light → low resistance → more voltage here
       │              │
       ├───────────── signal ──→ ADC pin
       │              │
    [27 kΩ]           │   dark → high resistance → less voltage here
       │              │
GND ───┴──────────────┘
```

## Step 3 — Read the light

Same `ReadRatio` as the knob, with the averaging helper from [Analog Input](analog-input.mdx#step-6--steady-the-reading) — sensor readings deserve it more than knobs do:

<Tabs groupId="board">
<TabItem value="flea" label="FEZ Flea" default>

```csharp title="Program.cs"
using System.Diagnostics;
using System.Threading;
using GHIElectronics.TinyCLR.Devices.Adc;
using GHIElectronics.TinyCLR.Pins;

// highlight-start
var adc = AdcController.FromName(FEZFlea.Adc.Controller1.Id);
var lightSensor = adc.OpenChannel(FEZFlea.Adc.Controller1.PA4);
// highlight-end

while (true) {
    double light = ReadAverage(10);

    Debug.WriteLine("Light: " + light.ToString("N3"));
    Thread.Sleep(200);
}

double ReadAverage(int samples) {
    double total = 0;

    for (int i = 0; i < samples; i++) {
        total += lightSensor.ReadRatio();
    }

    return total / samples;
}
```

Press **F5** and watch the Output window while you:

- **Cup your hand over the sensor.** The number drops.
- **Shine a phone light on it.** The number climbs.
- **Leave it alone.** It drifts slightly as clouds, screens, and people move.

Now compare with the knob in the last lesson, and notice three things:

1. **The range is not 0 to 1.** In a normal room you might see 0.3 to 0.8 and never reach either end.
2. **It's not linear.** Doubling the light doesn't double the reading — a photoresistor's resistance changes by ratio, not by amount.
3. **It's yours alone.** Your numbers depend on your room, your lamp, your sensor. Nobody else's thresholds will fit.

Which is why the next step measures rather than assumes.

## Step 4 — Calibrate to your room

Before deciding what "dark" means, find out what your own circuit actually reports. This program tracks the lowest and highest readings it has seen:

```csharp
double darkest = 1.0;
double brightest = 0.0;

while (true) {
    double light = ReadAverage(10);

    if (light < darkest) darkest = light;
    if (light > brightest) brightest = light;

    Debug.WriteLine("Light: " + light.ToString("N3") +
                    "   darkest: " + darkest.ToString("N3") +
                    "   brightest: " + brightest.ToString("N3"));

    Thread.Sleep(200);
}
```

Replace the `while` loop with it and press **F5**. For about 20 seconds:

1. Cover the sensor completely with your hand or a cup.
2. Uncover it and let the room light land on it.
3. Shine a phone light straight at it.

Write down your `darkest` and `brightest`. Halfway between them is a reasonable place to put a threshold:

```
threshold = (darkest + brightest) / 2
```

**Try the debugger:** instead of reading the numbers as they scroll past, set a breakpoint on `Debug.WriteLine(...)` and put `darkest` and `brightest` in the **Watch** window. Cover the sensor, press **F5**, and both values update at each stop.

## Step 5 — The night-light (and its flicker)

Now make a decision: below the threshold, the room is dark, so light the LED.

<TabItem value="flea" label="FEZ Flea" default>

```csharp title="Program.cs"
using System.Device.Gpio;
using System.Diagnostics;
using System.Threading;
using GHIElectronics.TinyCLR.Devices.Adc;
using GHIElectronics.TinyCLR.Pins;

// highlight-start
var adc = AdcController.FromName(FEZFlea.Adc.Controller1.Id);
var lightSensor = adc.OpenChannel(FEZFlea.Adc.Controller1.PA4);

using GpioController gpio = new GpioController();
int ledPin = FEZFlea.GpioPin.PA3;
// highlight-end

gpio.OpenPin(ledPin, PinMode.Output);

// Use the number you measured in Step 4.
const double Threshold = 0.45;

while (true) {
    double light = ReadAverage(10);
    bool dark = light < Threshold;

    gpio.Write(ledPin, dark ? PinValue.High : PinValue.Low);
    Debug.WriteLine("Light: " + light.ToString("N3") + (dark ? "   DARK" : ""));

    Thread.Sleep(100);
}

double ReadAverage(int samples) {
    double total = 0;

    for (int i = 0; i < samples; i++) {
        total += lightSensor.ReadRatio();
    }

    return total / samples;
}
```

Set `Threshold` to your own midpoint and press **F5**. Cover the sensor and the LED lights; uncover it and the LED goes out. Working night-light.

Now break it. Move your hand slowly until the reading sits **right at** the threshold, and hold it there. The LED stutters on and off, several times a second, following every tiny wobble in the reading.

That flicker is the same problem as switch bounce in [Digital Input](digital-input.mdx#step-7--filter-out-bounce), from a different direction: a signal that hovers at the deciding point crosses it over and over.

## Step 6 — Hysteresis

The fix is to stop using one threshold. Use **two**, and require the reading to travel a bit further before it changes its mind:

- Below **0.42** → it's dark, LED on.
- Above **0.48** → it's light, LED off.
- Anywhere between → **keep doing what you were doing**.

That gap is called **hysteresis**. Replace the `while` loop with:

```csharp
// Use numbers from your own Step 4 readings, a little either side of the midpoint.
const double DarkBelow = 0.42;
const double LightAbove = 0.48;

bool dark = false;

while (true) {
    double light = ReadAverage(10);

    if (light < DarkBelow) {
        dark = true;
    } else if (light > LightAbove) {
        dark = false;
    }
    // Between the two: leave `dark` alone.

    gpio.Write(ledPin, dark ? PinValue.High : PinValue.Low);
    Debug.WriteLine("Light: " + light.ToString("N3") + (dark ? "   DARK" : ""));

    Thread.Sleep(100);
}
```

Press **F5** and try to make it flicker again. Move your hand as slowly as you like — the LED switches once, cleanly, and stays put.

The state now lives in the `dark` variable, and the reading only changes it when it's clearly past one of the two edges. Widen the gap for a stickier decision, narrow it for a more responsive one.

**Try the debugger:** set a breakpoint on `gpio.Write(...)` and watch `light` and `dark` together in the **Locals** window while you move your hand. Inside the gap, `light` changes and `dark` doesn't — the whole idea, in one window.

## How it works

### Reading resistance with a voltage divider

The divider splits 3.3 V in proportion to the two resistances:

```
signal voltage = 3.3 V × 27 kΩ ÷ (27 kΩ + photoresistor)
```

| Light | Photoresistor | Signal | Ratio |
|---|---|---|---|
| Phone flashlight | ~2 kΩ | ~3.1 V | ~0.93 |
| Bright room | ~10 kΩ | ~2.4 V | ~0.73 |
| Dim room | ~50 kΩ | ~1.2 V | ~0.35 |
| Covered by hand | ~300 kΩ | ~0.27 V | ~0.08 |

These are examples, not your numbers — photoresistors vary a lot between parts, which is what Step 4 is for.

The fixed resistor sets where the sensor is most sensitive. Readings spread out most when the two resistances are similar, so 27 kΩ suits indoor light. A much smaller resistor would suit bright sunlight, a larger one near-darkness.

### Why the readings aren't linear

A photoresistor's resistance falls roughly by a fixed **ratio** for each doubling of light — the same logarithmic response your eyes have. Add the divider's own math on top, and the output is nowhere near a straight line. It's fine for "is it dark?", and unsuitable for "how many lux is that?" Sensors that answer the second question have the conversion built in and report real units over I²C.

### Thresholds and hysteresis

Any time a continuous signal becomes a yes-or-no decision, there's an edge — and real signals sit on edges and jitter. Hysteresis is the standard cure, and it's everywhere: thermostats that let the room drift a degree before switching, chargers that stop at 100% but don't restart until 95%, servers that scale up at 80% load and back down at 50%.

The rule of thumb: make the gap wider than your noise, narrower than the change you care about.

## Try this

1. **Sunrise, not switch.** Use PWM from [Breathing LED](breathing-led.mdx) to fade the LED brighter as the room gets darker, instead of switching it. A night-light with no threshold at all — is it better?
2. **Self-calibrating.** Keep the `darkest` and `brightest` tracking from Step 4 running all the time, and compute the two hysteresis edges from them, at 40% and 60% of the range.
3. **Alarm.** Add the buzzer from [Sound](sound.mdx) and beep when light suddenly *appears* — a "the drawer was opened" detector.
4. **Reverse the divider.** Swap the photoresistor and the 27 kΩ resistor. Readings now go up in the dark. Fix your logic to match, and see which arrangement you find easier to reason about.
