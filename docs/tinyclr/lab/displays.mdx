# Displays

Every lesson so far has reported its results to Visual Studio. Unplug the USB cable and your project goes quiet. A screen changes that: the board shows its own readings, and becomes something you can put on a shelf.

This lesson wires a common **I²C OLED** to either board and draws on it with **BasicGraphics** — text, shapes, a live sensor readout, and a scrolling graph.

About 45 minutes.

:::note[Parts not in the kit]
This lesson needs an **SSD1306 OLED**, the small monochrome 128×64 screen sold everywhere for a few dollars. Get the **I²C** version, which has four pins: GND, VCC, SCL, SDA.

Using a FEZ Bit? It already has a color screen built in — [FEZ Bit Screen](bit-screen.mdx) does this lesson on that, with no extra parts. This lesson still works on the Bit if you have an OLED.
:::

## What you'll learn

- How to talk to a display over **I²C**, using only two signal wires
- How BasicGraphics draws into a buffer, and why nothing appears until you send it
- How to lay out a readable readout on a tiny screen
- How to plot a live graph of a sensor

## What you'll need

- An **SSD1306 128×64 I²C OLED**
- From the kit:
  - Light sensor (photoresistor) and 1× 27 kΩ resistor — the divider from [Light and Logic](light-sensor.mdx#step-2--build-a-voltage-divider)
  - Jumper wires

| Also used | FEZ Flea | FEZ Bit |

## Step 3 — Hello, screen

<TabItem value="flea" label="FEZ Flea" default>

using System.Threading;

using GHIElectronics.TinyCLR.Drivers.BasicGraphics;

uint white = BasicGraphics.ColorFromRgb(255, 255, 255);

screen.Clear();
screen.DrawString("Hello!", white, 8, 8);
screen.DrawString("TinyCLR", white, 8, 28);

Press **F5**. Two lines of text appear on the OLED.

- **`BasicGraphics`** holds a picture in memory — nothing on the display yet. `Clear` and `DrawString` only change those bytes.
- **`oled.DrawBuffer(screen.Buffer)`** sends the whole picture over I²C. This is the moment the screen changes.
- **`ColorFormat.OneBpp`** means one bit per pixel: lit or dark, which is all this screen can do. The buffer is 128 × 64 ÷ 8 = **1024 bytes**.

Nothing on screen? Check SDA and SCL aren't swapped, and that the module is powered from 3.3 V.

## Step 4 — Shapes, and the drawing loop

Draw a few shapes, and make it move:

```csharp
int x = 0;

while (true) {
    screen.Clear();

    screen.DrawString("Shapes", white, 4, 2);
    screen.DrawRectangle(white, 4, 20, 40, 24);
    screen.DrawCircle(white, 76, 32, 12);
    screen.DrawLine(white, 0, 60, 127, 60);

    // A dot that walks across the bottom.
    screen.DrawCircle(white, x, 52, 3);
    x = (x + 4) % Width;

    oled.DrawBuffer(screen.Buffer);
    Thread.Sleep(50);
}
```

Replace everything after the `white` line with this and press **F5**.

Every frame follows the same three beats: **clear**, **draw**, **send**. Forget the `Clear` and old frames pile up; forget `DrawBuffer` and the screen freezes while your program happily draws to nothing.

**Try the debugger:** set a breakpoint on `oled.DrawBuffer(...)` and press **F5** repeatedly. Each press paints exactly one frame, and `x` in the Locals window matches the dot's position — animation, one step at a time.

## Step 5 — A live sensor readout

Now the point of having a screen: show a reading without a PC attached. This puts the light level on screen as a number and a bar.

<Tabs groupId="board">
<TabItem value="flea" label="FEZ Flea" default>

```csharp title="Program.cs"
using System.Threading;
using GHIElectronics.TinyCLR.Devices.Adc;
using GHIElectronics.TinyCLR.Devices.I2c;
using GHIElectronics.TinyCLR.Drivers.BasicGraphics;
using GHIElectronics.TinyCLR.Drivers.SolomonSystech.SSD1306;
using GHIElectronics.TinyCLR.Pins;

const int Width = 128;
const int Height = 64;

// highlight-start
var i2c = I2cController.FromName(FEZFlea.I2cBus.I2c1);
var adc = AdcController.FromName(FEZFlea.Adc.Controller1.Id);
var lightSensor = adc.OpenChannel(FEZFlea.Adc.Controller1.PA4);
// highlight-end

var oled = new SSD1306Controller(i2c.GetDevice(SSD1306Controller.GetConnectionSettings()));

var screen = new BasicGraphics(Width, Height, ColorFormat.OneBpp);
uint white = BasicGraphics.ColorFromRgb(255, 255, 255);

while (true) {
    double light = ReadAverage(10);
    int percent = (int)(light * 100);

    screen.Clear();

    screen.DrawString("LIGHT", white, 4, 2);
    screen.DrawString(percent + " %", white, 4, 20);

    // A bar that fills with the reading.
    screen.DrawRectangle(white, 4, 44, 120, 12);
    for (int i = 0; i < percent * 116 / 100; i++) {
        screen.DrawLine(white, 6 + i, 46, 6 + i, 53);
    }

    oled.DrawBuffer(screen.Buffer);
    Thread.Sleep(100);
}

double ReadAverage(int samples) {
    double total = 0;

    for (int i = 0; i < samples; i++) {
        total += lightSensor.ReadRatio();
    }

    return total / samples;
}
```

## Step 6 — A scrolling graph

A single number tells you *now*. A graph tells you what happened. Keep the last 128 readings — one per column — and slide them along:

```csharp
int[] history = new int[Width];

while (true) {
    double light = ReadAverage(10);

    // Shift everything left by one, newest on the right.
    for (int i = 0; i < Width - 1; i++) {
        history[i] = history[i + 1];
    }
    history[Width - 1] = (int)(light * 40);     // 0…40 pixels tall

    screen.Clear();
    screen.DrawString("LIGHT " + (int)(light * 100) + "%", white, 2, 2);
    screen.DrawLine(white, 0, 62, 127, 62);      // baseline

    for (int i = 0; i < Width; i++) {
        screen.SetPixel(i, 61 - history[i], white);
    }

    oled.DrawBuffer(screen.Buffer);
    Thread.Sleep(100);
}
```

Press **F5** and wave your hand over the sensor, or walk past a lamp. The trace scrolls right to left, and about 13 seconds of history fits on screen.

This is the shape of every data logger: sample, store, shift, draw.

## How it works

### I²C in one minute

I²C connects many devices to the same two wires. **SCL** is a clock the board generates; **SDA** carries the bits. Every device has an **address**, and a message begins with the address of whoever it's for — so the OLED ignores traffic meant for a sensor sharing the same pins.

`SSD1306Controller.GetConnectionSettings()` fills in the display's address and speed, which is why you never see them in the code. Adding an I²C sensor later means another `GetDevice` call on the same controller, and no more wires.

Unlike GPIO or PWM, the pins aren't yours to choose: SDA and SCL are fixed by the chip, which is why the [pin reference](#pin-reference) names exactly two.

### Buffer, then send

`BasicGraphics` never touches the display. It owns an array of bytes and draws into it, and `Buffer` hands you that array so a display driver can send it.

That separation is why the same drawing code can target an OLED, a color LCD, or an LED matrix. It's also why every frame ends with `DrawBuffer`: an update is one transfer of the whole picture, which keeps the screen from showing half-drawn frames.

In `OneBpp` mode, each byte holds **eight vertically stacked pixels** — the layout the SSD1306 expects, so no conversion is needed between the two.

### Drawing on a small screen

128×64 pixels is about 21 characters across in the built-in font. A few habits help:

- **Label every number.** `"LIGHT 42%"` beats `"42"`.
- **Round aggressively.** `(int)(light * 100)` is more readable than four decimals that flicker.
- **Use a shape for the trend and digits for the value.** The bar in Step 5 reads instantly; the number is there when you want precision.

### Bigger screens

The SSD1306 is monochrome and small on purpose: it's cheap and needs two wires. Color displays with more pixels connect over [SPI](../feature/spi.mdx) and are driven the same way — BasicGraphics in `Rgb565` mode, or the full [graphics engine](../feature/graphics.mdx) on SC20xxx hardware. [FEZ Bit Screen](bit-screen.mdx) does exactly that on the Bit's built-in display, and [Extended Features → Displays](../drivers/displays.mdx) lists the other supported controllers.

1. **Distance meter.** Swap the photoresistor for the [Distance Sensor](distance-sensor.mdx) and show centimeters with a bar that grows as things get closer.
