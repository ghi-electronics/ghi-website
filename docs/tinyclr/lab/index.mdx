# Electronics Lab for the .NET Developer

Project-based lessons that take you from blinking an LED to buttons, sound, servo control, analog sensing, and ultrasonic distance measurement — all in **C#**, with the **Visual Studio debugger attached to real hardware**. Set a breakpoint and the board stops with it. Hover a variable to read a sensor.

If you can write a loop and a method, you're ready. No electronics background needed, no soldering, no new IDE.

This page covers everything you need before the [first lesson](digital-output.mdx): setting up your PC, getting to know your board, and the wiring basics every lesson builds on. Already comfortable with breadboards? Skim [your board's pins](#get-to-know-your-board) and jump straight in.

:::tip[Stuck? Ask us]
Post in the **[TinyCLR forum](https://forums.ghielectronics.com/c/tinyclr/12)** — the people who write the runtime and ship the kits read and answer there. Tell us your board, which lesson, and what you saw; a photo of your wiring helps.
:::

## Set up and blink

Five minutes, and you've proved your PC, your board, and the tools all work together. This is also the exact workflow every lesson uses.

:::note[What we assume you already have]
These lessons teach **electronics**, not C# or .NET setup. Before starting, your PC should already build and run a plain C# "hello world", and you should be comfortable **adding NuGet packages** to a project — every lesson begins by installing a couple.

In **Visual Studio** that means the **.NET desktop development** workload is installed. In **VS Code** it means a **.NET SDK**, installed directly or by an extension that brings it along. If a hello world builds and runs, the TinyCLR tooling has what it needs.
:::

1. **Install Visual Studio 2026** — any edition, including the free [Community Edition](https://www.visualstudio.com/downloads/) — with the **.NET desktop development** workload.
2. **Install the TinyCLR extension.** `Extensions` → `Manage Extensions…`, search for `tinyclr`, install **TinyCLR OS Project**, restart Visual Studio.
3. **Create a project.** `Create a new project` → pick **TinyCLROS** from the Platforms dropdown → **TinyCLR Application** → name it and click **Create**.
4. **Install the NuGet packages.** Right-click the project → `Manage NuGet Packages…` → **Browse**, then add **`GHIElectronics.TinyCLR.Devices.Gpio`** and **`GHIElectronics.TinyCLR.Pins`**. Each lesson lists the packages it needs in Step 1.
5. **Plug your board into USB** and replace `Program.cs` with:

<Tabs groupId="board">
<TabItem value="flea" label="FEZ Flea" default>

```csharp title="Program.cs"
using System.Device.Gpio;
using System.Threading;
using GHIElectronics.TinyCLR.Pins;

using GpioController controller = new GpioController();

int ledPin = FEZFlea.GpioPin.Led;
controller.OpenPin(ledPin, PinMode.Output);

while (true) {
    controller.Write(ledPin, PinValue.High);
    Thread.Sleep(500);

    controller.Write(ledPin, PinValue.Low);
    Thread.Sleep(500);
}
```

</TabItem>

6. **Press F5.** Visual Studio builds, finds your board, deploys, and attaches the debugger — and the on-board LED blinks.

That's it. Every lesson from here is the same four moves: new project, add packages, paste code, press **F5**.

:::tip[Deploy failed with a checksum error?]
If the Output window shows something like this:

```
Error: the reference mscorlib cannot be used with this version of the firmware.
Firmware checksum 0x8FF20F1B does not match the assembly checksum 0x04F4012C.
```

your board's firmware is older than the NuGet packages you just installed. [Install or update firmware](../getting-started.mdx#install-or-update-firmware) sorts it out in a couple of minutes. Otherwise there's nothing to do — kits ship ready to run.
:::

TinyCLR development requires **Windows**. The lessons use **Visual Studio** for screenshots and shortcuts; [VS Code](../tutorial/vscode.mdx) works too, with its own project type. The C# is identical either way, and so are **F5**, **F10**, and **F11**.

## Get to know your board

Each pin has a **name** you use in code, and a set of **functions** that tell you what else it can do. Lessons tell you which pin to use — this is the map to find it.

| Function | What it does | First used in |
|---|---|---|
| **GPIO** | Digital input or output. Every signal pin can do this. | [Digital Output](digital-output.mdx) |
| **PWM** | Generates pulses — for dimming LEDs, mixing colors, making tones, and driving servos. | [Breathing LED](breathing-led.mdx) |
| **ADC** | Reads an analog voltage — for knobs, light sensors, and joysticks. | [Analog Input](analog-input.mdx) |
| **I²C, SPI** | Buses for displays and sensors. | [Displays](displays.mdx) |
| **3.3V, 5V** | Power for the parts on your breadboard. | [Analog Input](analog-input.mdx) |
| **GND** | Ground — the 0 V reference every circuit returns to. | [Digital Output](digital-output.mdx) |

**Setting up:** push the Flea into the breadboard so it **straddles the center gap** — its two rows of pins on opposite halves. That way every pin gets its own row, and no two pins are shorted together. Parts connect by sharing a row with a pin, or with a pin-to-pin jumper wire.

**Power:** the single USB-C cable does everything — loads your code and powers the board. The Flea's **3V3** and **5V** pins power the parts on your breadboard.

**Setting up:** slide the FEZ Bit into the adapter board's edge connector, display facing up. The adapter brings every pad on the FEZ Bit out to a **row of male header pins** next to the breadboard. Connect a header pin to a breadboard row with a **pin-to-socket (male-to-female) jumper wire** — the socket end goes on the header pin.

![2-USB](/img/docs/2-usb.webp)


**Power:** the FEZ Bit kit uses two USB cables:

- **USB-C → FEZ Bit** — loads and debugs your code.
- **Micro USB → adapter board** — powers the adapter's regulator, which provides **5V** and **3.3V** on the header for the parts on your breadboard. It powers the FEZ Bit too.

While you're coding, plug in both. When you're done, unplug the USB-C cable — the adapter's micro USB cable alone keeps your project running.

:::

## How a breadboard works


A breadboard lets you build circuits by pushing parts and wires into holes — no soldering. Inside, metal strips connect certain holes together:

- **Rows of five.** Each short row of five holes (for example, `a`–`e` in row 10) is connected. Anything plugged into the same row is wired together.
- **The center gap.** The channel down the middle separates the two halves. Row 10 `a`–`e` is **not** connected to row 10 `f`–`j`.

![Wiring Diagram](/img/docs/breadboard-wiring.webp)

- **Power rails.** The long strips along the edges, marked **+** (red) and **−** (blue), run the length of the board. Connect them to **3.3V** and **GND** once and every part can reach power from anywhere.

![Wiring Diagram](/img/docs/breadboard-power.webp)

:::tip
On some breadboards the power rails are split in the middle — a gap in the red and blue lines is the giveaway. Bridge the halves with a short jumper if you need power along the full length.
:::

## Jumper wires

- **Pin-to-pin (male-to-male)** — for connecting holes on the breadboard to each other.
- **Pin-to-socket (male-to-female)** — for modules with header pins, like the distance sensor, joystick, and servo — and for the FEZ Bit adapter's header pins.

Wire color doesn't affect the circuit, but a habit makes circuits easier to check: **red for power**, **black for GND**, other colors for signals.

## Parts you'll meet first

### LEDs

An LED only lights when current flows in one direction:

- The **longer leg** is the **anode** (+). It connects toward the pin.
- The **shorter leg** — next to the **flat edge** of the LED's rim — is the **cathode** (−). It connects toward GND.

Put one in backwards and it simply stays dark — no harm done. Flip it around.

### Resistors

Resistors limit current, and they have **no polarity** — either direction works, so you can't put one in backwards. The kit has two values:

| Value | Used for | On the paper strip | 5-band code | 4-band code |
|---|---|---|---|---|
| **220 Ω** | Every LED — 10 in the kit | `220R` | red · red · black · black · brown | red · red · brown · gold |
| **27 kΩ** | Pull-ups and pull-downs — 5 in the kit | `27K` | red · violet · black · red · brown | red · violet · orange · gold |

Two things trip people up the first time:

- **`220R` means 220 Ω.** The letter sits where the decimal point would go, which keeps a smudged dot from changing the value. So `4K7` is 4.7 kΩ, and `1M0` is 1 MΩ.
- **Your resistors have five bands, not four.** Most charts online show four. With five, the first **three** bands are digits instead of two, the fourth is the multiplier, and the last is tolerance — a brown final band means ±1%. Both codes are in the table above, so you can match whichever chart you find.

The easiest approach: leave them on the labeled strip until you need one. Each lesson says which value to use and why.

## Wiring habits

These five habits prevent almost every beginner mistake:

1. **Unplug USB while wiring** — both cables on the FEZ Bit. Plug back in when the circuit is complete.
2. **Never connect 3.3V or 5V directly to GND.** That's a short circuit.
3. **Never connect two pins that are both outputs.** If one drives high and the other low, the chip can be damaged.
4. **Always use a resistor with an LED.** [Digital Output](digital-output.mdx#why-the-resistor-matters) explains why.
5. **Check your wiring against the lesson before powering up.** Most "my code doesn't work" moments are one wire in the wrong row.

:::warning
Signal pins run at **3.3 V** and can supply only a few milliamps — enough for LEDs and signals, not for motors or bright lamps. Parts that need more, like the servo, get their power from the **5V** pin, and that lesson shows how.
:::

## The lessons

Work through them in order — each one builds on the last:

- **[Digital Output](digital-output.mdx)** — control your first LED, understand current-limiting resistors
- **[Digital Input](digital-input.mdx)** — buttons and pull-up resistors — the kit's 27 kΩ resistors first, then the chip's built-in ones — plus events and a multi-button reaction-time game
- **[Breathing LED](breathing-led.mdx)** — control power level with pulse-width modulation
- **[RGB LEDs](rgb-leds.mdx)** — mix colors, first with digital outputs, then with PWM for any color
- **[Sound](sound.mdx)** — frequency, pitch, and a melody on a piezo buzzer
- **[Servo Motor](servo-motor.mdx)** — positioning with pulses
- **[Analog Input](analog-input.mdx)** — the potentiometer as a dimmer; watch the ADC live in the debugger
- **[Light and Logic](light-sensor.mdx)** — a photoresistor night-light with hysteresis
- **[Joystick](joystick.mdx)** — a fun project: steer the servo or mix RGB colors with your thumb
- **[Distance Sensor](distance-sensor.mdx)** — measure distance with ultrasound, and see why a radar is just a distance sensor that moves

- **[Displays](displays.mdx)** — add a small I²C OLED: text, shapes, a live readout, and a scrolling graph
- **[FEZ Bit Screen](bit-screen.mdx)** — the same readout in color on the FEZ Bit's built-in display, with nothing to wire
- **[Addressable LEDs](addressable-leds.mdx)** — WS2812 / NeoPixel strips: color, brightness, and animation from C#

The last three need a part beyond the kit, except **FEZ Bit Screen**, which uses the display already on the board — each lesson lists exactly what to get.

Every lesson has a wiring photo, a schematic, and copy-paste C# code. And because your board runs with the debugger attached, breakpoints and variable inspection work everywhere — lessons point out the spots worth a look.
